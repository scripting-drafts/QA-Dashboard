# Ticket quality rules

Drafts are generated by `sentinels/tickets.py`; the rules below are code, not
guidance. They exist because a real GNOME Shell crash was routed to Mozilla,
labelled WebRender, and given Firefox reproduction steps.

## Ownership

Resolved in this order by `classify.vendor_for_crash`:

1. **Faulting driver module** — a frame inside `libnvidia*`, `libcuda`, `nvrm`
   goes to NVIDIA, whatever process loaded it.
2. **Process anchor** — the crashing executable owns the bug. Shared libraries
   never decide ownership: GNOME Shell embeds SpiderMonkey (`libmozjs`), so
   every gjs stack contains `mozilla::`; Firefox embeds GTK, so every Firefox
   stack contains `g_object_unref`. `libmozjs`, `mozilla::detail`, `compositor`
   and bare `js::` are deliberately absent from the Mozilla content rule.
   GNOME unit names (`org.gnome.*`) are recognised as GNOME.
3. **Content rules over the header only** — for processes that are not a known
   component, the evidence is the crash header plus the *faulting frame*
   (`crash.identity_text` + `crash.faulting_frame`). The `Found module` dump is
   never read: it lists every loaded library (`libsystemd`, `libdbus`,
   `libnvidia`) and used to file Python and Electron crashes against systemd
   or the GPU driver.

The fault-core `hardware` override still applies when the process has no owner
and its affinity included the fault CPUs.

## Component

`classify.component_for_issue` is **total**: every issue gets a label, and
`unknown` is never returned. The steps are evidence-first and do not depend on
whether the vendor was classified:

| First match | Component |
|---|---|
| faulting module | project: `mutter`, `gjs`, `cairo`, `gtk`, `xorg-server`, `NVIDIA driver`, `Firefox` |
| process/executable | friendly stem: `gnome-terminal`, `python3.10`, `electron`, `opencode` |
| event unit/scope | unit stem: `systemd-coredump`, `snap.snapd-desktop-integration` |
| finding rule/subject | subject (`kernel`, `smartmontools`) or rule prefix (`journal`, `systemd`, `faultcore`) |
| nothing usable | `unassigned` |

Vendor-specific clamps keep tracker fields real:

- **Mozilla**: WebRender / JavaScript Engine / `Firefox :: Untriaged`; GTK or
  X11 frames become `Core :: Widget: Gtk`, cairo frames `Core :: Graphics`.
- **GNOME**: `mutter`/`gjs` from the faulting module, then the process
  (`gnome-shell`, `gnome-terminal`, `gnome-software`, `nautilus`); the default
  is `gnome-shell`.
- **NVIDIA / kernel / netplan / hardware** keep the vendor product label.
- **Local and systemd** use the descriptive chain above; `python3.10` is a
  local-triage label, not a tracker component.

A component is never inferred from the vendor alone when the evidence names
something else: a mis-routed `systemd` ticket for a Python/X11 crash still says
`xorg-server`, not `systemd`. Structured trackers (Mozilla, NVIDIA, kernel,
netplan, hardware) are the exception: they keep a real tracker component
because inventing a field would make the ticket unfilable; a wrong route there
is a routing bug to fix separately.

## Crash evidence

`crash.digest` keeps the header (size, pid, signal, timestamp, command line,
executable) and the crashing thread's stack, and drops the `Found module` dump
that otherwise consumes any fixed-size prefix.

`crash.faulting_frame` skips the process's signal handler: when a process
catches SIGSEGV, frames `#0..#3` are `pthread_kill`/`raise`/handler/
`__restore_rt` and the fault starts after the trampoline. Drafts name that
frame and state how many frames the handler covers.

A `module + 0x…` frame is the nearest exported symbol, not a debug symbol.
Drafts say so instead of presenting the name as exact.

## Reproduction

The reproduction block is selected by component and crash family:

- **GNOME** — session type, extension list, the window action in the stack,
  matching debug symbols, and the project that owns the faulting frame.
- **Firefox crash** — the existing fresh-profile and `about:crashes` steps.
- **Mozilla event/finding, non-browser process** — reproduce the logged
  action; no browser profile and no page-load guess.

## Fault-core tag

The `[fault core …]` title suffix and the correlation section appear only when
the ticket is a correlation, a kernel/hardware ticket, or a row's own affinity
included the fault CPUs. A library that happens to be linked into the crashing
process is not a CPU correlation.

## Redaction

`util.redact` must not destroy the evidence it protects:

- `::` without a hex digit is prose (`Core :: Graphics`), not IPv6.
- systemd unit and slice names (`org.gnome.Shell@x11.service`,
  `user@1000.service`) are not e-mail addresses and are preserved.
- Real addresses, MACs, UUIDs, serials, hostnames, home paths and e-mail
  addresses are still removed. Submitted crash IDs are preserved.

## Re-routing an existing ticket

`raise_ticket._align_vendor_name` renames the vendor prefix when ownership
changes, and `_already_staged` treats a vendor change as material so the body
and manifest are rewritten. The signature hash keeps the ticket identity, and
the lifecycle log records a `renamed` event.
