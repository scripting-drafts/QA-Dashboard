QA Sentinels Documentation

Local monitoring, evidence collection, and ticket preparation.

What QA Sentinels does

QA Sentinels periodically samples the host, examines journal and crash records, and organizes findings into reports and verifiable evidence bundles. When an incident needs closer inspection, it can queue a more privileged tracing run. It correlates repeated failures and prepares vendor bug-report drafts; it never submits tickets automatically.

How it works

ComponentPurposeRuns when
Layer 1 Capture CPU, memory, kernel, process, and journal evidence; detect possible incidents. Every minute via cron or systemd, or manually.
Boot analysis Classify prior boots as CLEAN, UNCLEAN, or UNKNOWN; flag unexplained stops. During monitoring and analysis.
Correlation Connect recurring signatures to preceding events and prepare vendor ticket drafts. On demand or through the configured workflow.
Layer 2 Collect additional ftrace, perf, and optional eBPF diagnostics for selected findings. When a deep-trace request is queued or manually invoked.

The core uses a C sampler, the Python 3 standard library, SQLite WAL, and cron or systemd. All collected data stays on this machine.

Ticket workflow

Drafts are generated automatically for each issue grouped by vendor and signature. A draft reaches the raise bucket only when all viability checks pass. Anything else moves to standby or rejected with the failing reason recorded. A human posts tickets to the vendor tracker.

  • raise/ — passed all checks; ready for human review.
  • standby/ — a check failed; retained with its reason.
  • rejected/ — a held or outdated package explains the crash.
  • raised/ — legacy archive for manually posted tickets.

Safety and privacy

  • The Database window runs read-only SELECT, WITH, or EXPLAIN statements only.
  • The dashboard builds an argument vector; QA Sentinels enforces limits and validates SQL.
  • Tickets are never submitted automatically; a human posts them.
  • Captured data remains local. Credentials and token values are never shown in the renderer.
  • Core-2 affinity is retained as diagnostic context for correlated crashes.
